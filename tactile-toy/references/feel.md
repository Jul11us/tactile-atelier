# 手感：弹簧阻尼 + 顶点着色器

手感决定了这个玩具好不好玩，也是最容易写成"能动但不好玩"的部分。下面的做法和数值都来自系列页面（主要是 jelly-bricks 和 mochi-pets），可以直接照抄再调。

## 1. 核心分工：位置交给物理，形变交给弹簧

- **位置和旋转**由物理决定：用 cannon-es 刚体（要堆叠、推倒、轨道的时候），或者手写的重力 + 地面 + 两两推开（团子、泡泡这类圆东西）。
- **形变**（压扁、拉长、剪切晃动、戳出的坑）由每个物件自己的几根弹簧决定，只影响画面，**不反馈回物理**。物理碰撞体一直是原来那个方块或球。

这样做的好处：物理稳定（碰撞体不变形），形变可以夸张（只是视觉），而且便宜（几根标量弹簧 + 一段顶点着色器）。

**叠起来的东西要整体晃**：每个物件记住"托着我的是谁"（`sup`），渲染时把下面那块的剪切和压扁累加成自己的位置偏移：

```js
b.off.set(0,0,0);
if(b.sup){ b.off.copy(b.sup.off); b.off.x+=b.sup.sh.x*H; b.off.z+=b.sup.sh.y*H; b.off.y-=b.sup.sq*H; }
mesh.position.copy(body.position).add(b.off);
```

再让上面那块的剪切弹簧被下面那块牵着走：`shV += (sup.sh - sh) * k*0.25 * dt`。于是整座塔像一根果冻柱一样摆，而不是每块各晃各的。

## 2. 弹簧

```js
// x 追 target。k 刚度，z 阻尼比（<1 会过冲回弹）
v += (-k*(x-target) - 2*Math.sqrt(k)*z*v) * dt;  x += v*dt;
```

模板里的 `Spring` 类就是这两行。

**滑块就是"性格"**：一个 0–1 的滑块同时调软硬和晃动，而且所有弹簧共用这一组：

```js
const k = 300 - 230*knob;              // 70（软）… 300（硬）
const z = 0.3 - 0.22*knob;             // 0.08（晃很久）… 0.3（很快停）
```

滑块的名字要说人话：Wobble、Squish、Softness、Breeze、Flow。

**子步**：k 到 300、dt 到 1/30 的时候，显式积分会炸。每帧把弹簧拆成 4 个子步：`for(i<4) springs(b, dt/4)`。

**夹紧**：每根弹簧都要夹在合理范围里，偶尔一次大冲量也不会把物件扭成麻花：

| 量 | 范围 |
|---|---|
| 压扁 `sq` | −0.3 … 0.5（负数就是被拉高） |
| 剪切 `sh`（二维） | 长度 ≤ 0.35 |
| 拉长 `st` | −0.2 … 0.6 |
| 团子的整体缩放 `s` | −0.4 … 0.55 |

拉长弹簧用 `k*0.8`、阻尼 `c*0.8`，比压扁稍软，拉开的东西回得慢一点更像有黏性。戳出的坑用 `k*1.4`、阻尼 `c*0.9`，回得快。

## 3. 事件 → 冲量对照表

手感就是"什么事件给哪根弹簧踢一脚、踢多大"：

| 事件 | 冲量 | 出处 |
|---|---|---|
| 落地 / 碰撞 | `sqV += min(碰撞法向速度,12)*0.55`，只在速度 > 1.2 时触发；剪切往速度反方向踢 `shV -= vel.xz*0.08` | jelly-bricks |
| 被戳一下 | 坑 `paV += 4.5`，余震 `wob = max(wob,0.01*力度)`（之后每帧 `wob *= exp(-2.2dt)`） | mochi-pets |
| 按住不放 | 压扁目标随按住时间涨：`sT = min(0.42, t*1.2)`；松手 `sT=0`，弹簧自己弹回去并过冲 | mochi-pets |
| 跳之前 | 先蹲：起跳前 0.25 秒 `sT=0.22`，起跳瞬间 `sT=0, sV+=3` | mochi-pets |
| 叠上去 / 吸附 | 上面那块 `sqV += 4.5`，下面那块 `sqV += 2.5` 再加一点随机剪切 ±0.75 | jelly-bricks |
| 两个物件相撞 | 两边都在接触点"戳"一下，力度 = `min(相对速度,4)` | mochi-pets |
| 底座加速、急停（被拖着走、撞墙、撞到别人） | 惯性：每帧 `剪切V -= (这帧速度 - 上帧速度)*0.35`。起步时顶部往后仰，急停时往前甩然后来回晃。0.5 太大，一拖就顶到剪切上限 | Nº 22 布丁测试 |
| 空格摇一摇 | 随机方向的剪切冲量，越高的层越大：`2.2 + 层数*0.9`，底层 1.2 | jelly-bricks |

## 4. 抓、拉、拖、扔

这是"抓起来会被拉长、松手会回弹"的完整流程（jelly-bricks 的 `updateHeld`）：

1. **按下**：射线选中物件，物体切成 `KINEMATIC`（不再受重力，但还能推别人），速度清零，光标 `#cur` 加 `.hold` 缩小变实心。
2. **拉（pull）阶段**：物件先不动，只是朝光标方向被拉长：`dir = 光标点 - 按下点`（y 加 0.25 让它略微向上），`stT = min(长度*0.2, 0.5)`。
3. **拉开（lift）**：拉的距离 > 1.0，或按住 > 0.3 秒且距离 > 0.35 时才真正提起来。这一下"扯开"的瞬间就是手感。提起时解开它和上面物件的连接，上面的物件就会掉下来（见第 7 节）。
4. **拖**：目标点在一个水平面上（高度要越过下面所有东西：`max(下方最高点+HH+0.9)`），位置用指数平滑跟随：`pos.lerp(target, 1-exp(-11*dt))`。用这一帧和上一帧的差算出速度留着。
   - 往移动方向倾斜：`角度 = min(速度*0.035, 0.38)`。
   - 落后量 `lag = target - pos` 就是拉长方向：`stT = min(|lag|*0.18, 0.35)`。快拖就被甩长，停下就缩回去。
5. **松手**：切回 `DYNAMIC`，速度用拖拽时估出的那个，但 `clampLength(0,8)`、`y = min(y,3)`，扔得出去但不会飞出屏幕。`stT=0`，拉长弹簧自己弹回来并过冲一下。
6. **落到别的物件上方时吸附**（可选，积木类）：找下面最高的那块，对齐 90° 朝向和网格，直接摆上去，用 `LockConstraint(maxForce:400)` 粘住，再给两块各踢一脚压扁（见第 3 节）。刚吸附的物件有 0.8 秒 `settle`：每帧把速度乘 0.2，之后让它 `sleep()`，不会自己滑下去。

不用物理库的版本（mochi-pets）更简单：在一个面向相机的竖直平面上拖，移动超过 0.35 才算"拖"，否则算"按住挤压"。

## 5. 形变怎么画上去

**A. 顶点着色器（首选，单个 mesh 的物件）**：模板里的 `softMaterial()`。用 `onBeforeCompile` 往 `MeshPhysicalMaterial` 里注入一个 `soft()` 函数，替换 `#include <begin_vertex>`。所以透射、清漆、环境反射全都保留，只是顶点被挪了。

- 每个物件一份材质实例（因为 uniform 各不相同），但 `customProgramCacheKey=()=>'soft'` 让它们共用一个编译好的 shader。
- 剪切和拉长方向是**物件局部坐标**：每帧用物件旋转的逆把世界方向转进去：
  ```js
  qi.copy(mesh.quaternion).invert();
  v3.set(sh.x,0,sh.y).applyQuaternion(qi); u.uShear.value.set(v3.x,v3.z);
  u.uDir.value.copy(dir).applyQuaternion(qi).normalize();
  ```
- `uHH` = 几何体半高（几何体单位），`uExt` = 最长边的一半。
- 戳的坑：`uPoke` 是局部空间里的方向，用 `mesh.worldToLocal(命中点).normalize()` 算。

**B. 整体缩放（物件是一组 mesh，比如有眼睛有嘴的团子）**：给外层 group 缩放，保体积：

```js
const sy = Math.max(0.3, (1-s)*(1+st)), sxz = 1/Math.sqrt(sy);
group.scale.set(sxz, sy, sxz);
```

脸跟着一起变形，表情才不会穿帮。再叠一个顶点着色器的戳坑和余震。

**C. 高度场（沙、黏土、可以被按出印子的表面）**：一张细分很高的 `PlaneGeometry`（sand-garden 是 220×150），高度存在 `Float32Array`，改了才写回顶点并 `computeVertexNormals()`（用 `dirty` 标记，不要每帧都算）。黏土的"记得每一次按压，但只记一阵子"是每帧把高度往原样慢慢松回去，再加一点扩散（clay-stamp）。

## 6. 不用物理库时手写的物理

团子、泡泡、挂件这类不需要真刚体的，手写更轻也更好控制（mochi-pets）：

- 重力 `vel.y -= 18*dt`（比真实的 9.8 大，动作更利落）。
- 落地：`pos.y<=0` 时，如果下落速度 > 2，先把压扁弹簧往下踢 `sV -= min(-vel.y*0.55, 8)`，再把 y 速度清零，水平速度按 `exp(-6dt)` 衰减（摩擦）。
- 两两推开：按水平距离和半径和算重叠，各推一半；相对速度 < −0.3 时交换速度分量，并在接触点各戳一下。
- 边界：超出半径 `BOUND` 就拉回来，速度反向乘 0.5。
- 待机：每个物件有一个随机倒计时，到了就蹲一下然后跳一下，朝场地中心方向。画面里永远有一点东西在动，但不吵。

## 7. 爽点的分寸

爽点要"活泼但不要像爆炸"。具体就是这几条：

- **推倒**：提起下面一块时，先解开它上面整串的粘连，再给上面 3.5 范围内的物件一点随机速度：水平 ±0.8，向上 +1，角速度 ±1.5。是"晃一下然后塌下来"，不是被炸飞。
- **粘是软粘**：`LockConstraint` 的 `maxForce:400`，受力大时允许被拉开一点，不会焊死成一整块铁跟着飞。
- **弹性低**：物件之间 `restitution:0.03`、物件和地面 `0.2`，`friction` 0.95 / 0.7。看起来弹，是因为形变弹簧在弹，不是物理在弹。
- **重力稍大**：cannon 里用 `-22`，掉落干脆。`solver.iterations:14`，开 `allowSleep` 和 `SAPBroadphase`。
- **四面看不见的墙**：在 ±14 放静态平面，东西不会滚出画面。
- **所有速度都有上限**：扔出 ≤ 8，向上 ≤ 3，碰撞冲量 ≤ 12。

## 8. 声音（可选）

声音能让爽点更爽（风铃、弹珠、爆米花用了），但必须在第一次点击之后才能创建 `AudioContext`（浏览器自动播放限制）。全部用 WebAudio 现场合成，不加载音频文件：

- 总线：`DynamicsCompressor` → 输出；混响用一段指数衰减的白噪声做 `ConvolverNode` 的脉冲响应（2.5 秒，湿声 0.35）。
- 玻璃管：四个泛音，频率比 `[1, 2.76, 5.4, 8.93]`，音量 `[1, 0.45, 0.22, 0.1]`，衰减 `[4.5, 2.2, 1.1, 0.6]` 秒，4ms 起音，频率随机偏 ±0.1%，按管子位置左右声像。
- 音量和碰撞强度挂钩，并设上限（风铃是 0.35）。
